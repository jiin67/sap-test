# 회수품 적합성 관리 사용 설명서

| 항목 | 내용 |
|---|---|
| 대상 | T-code `ZCRM052` → 프로그램 `ZCRMR052` (일반)<br>T-code `ZCRM052S` → 프로그램 `ZCRMR052S` (구독 전용) |
| 작성 기준 | KDQ 클라이언트 210, 로그온 언어 KO, 2026-09-10 실측 |
| 작성일 | 2026-09-10 |

두 프로그램은 **구독 데이터 필터를 빼면 화면과 동작이 같다.**
아래 설명은 양쪽에 공통으로 적용되며, 다른 부분만 따로 표시한다.

> **표기 규칙**
> - **[실측]** … 이 문서 작성 과정에서 화면·DB로 직접 확인한 내용
> - **[개발가이드]** … 개발 문서에 근거한 내용. 화면으로 직접 확인하지 않았다

## 1. 전체 흐름 한눈에 보기

```
① 선택화면 (screen 1000)
   조회조건 입력 → 실행(F8)
        │
        │  ZCRM_CICSVC ─┬─ ZCRM_REQ ─┬─ ZCRM_RECPT
        │  (상담·서비스)  │  (회수품요청) │  (회수품접수)
        │                │             └─ ZCRM_RECPT_WEAR
        │                └─ MVKE (제품계층, INNER JOIN)
        ▼
② 결과화면 (screen 100)
   ALV 목록 + 접수부서/접수자 입력란
        │
        │  적합수량·부적합수량·부적합사유·책임사업장·입고일자 입력
        │
        ▼  저장(Ctrl+S) → "저장 하시겠습니까?" → 예
③ 업무 검증 6종 통과 시 저장
        │
        ├─ ZCRM_RECPTNO   접수번호 채번 (일자 + 순번)
        ├─ ZCRM_RECPT     접수·적합성 판정 결과
        └─ ZCRM_RECPT_WEAR 회수품 실제 입고일자
```

| 접수여부 = 회수품 미접수 | — | 접수일자 |

### 2.4 실행

`실행` 버튼 또는 **F8**.

> **주의 [실측]** 조회 범위가 넓으면 매우 오래 걸린다.
> 센터조치 + 회수품 접수 기준으로 2026.01.01~09.09 을 조회하면 71,912건이고
> 수 분이 걸린다. **15일 이내로 끊어서 조회할 것을 권장한다.**
> 15일이면 센터조치 약 5,300건, 서비스점조치 약 1,000건이다.

## 3. 조회 시 읽어오는 테이블

### 3.1 조회 흐름 **[개발가이드]**

```
ZCRM_CICSVC (상담·서비스 처리 원천)          Key: CSLTNO + CSLTNO_ITEM
      │  CSLTNO = CSLTNO, CSLTNO_ITEM = CSLTNO_ITEM
      ▼
ZCRM_REQ (회수품 요청)                        Key: REQNO + REQNO_ITEM
      │  REQNO = REQNO, REQNO_ITEM = REQNO_ITEM
      ▼
ZCRM_RECPT (회수품 접수·적합성 판정)          Key: RECPTNO + RECPTNO_ITEM
      │
      ├─ ZCRM_RECPT_WEAR (회수품 실제 입고일자)
      └─ ZCRM_QRST_PRT   (회수품 품질검사 결과·마감상태)
```

`ZCRM_CICSVC-MATNR` 로 **`MVKE` 를 INNER JOIN** 한다
(`VKORG = 'ASKR'`, `VTWEG = '10'`). 이 조합이 없는 자재는 **조회되지 않는다.**

### 3.2 접수 / 미접수 구분 **[개발가이드]**

| 접수여부 | 대상 |
|---|---|
| 회수품 접수 | `ZCRM_RECPT` 에 해당 요청이 있고 `STATUS = 'X'` 인 건 |
| 회수품 미접수 | `ZCRM_RECPT` 에 없거나 `STATUS <> 'X'` 인 건 |

공통 전제조건: `ZCRM_REQ-TAGNO1` 이 있어야 하고 `ZCRM_REQ-REQ_DROP <> 'X'` 여야 한다.

### 3.3 구독 전용 프로그램의 추가 조건

`ZCRMR052S` 는 접수 SELECT 와 미접수 SELECT 양쪽에 아래 조건이 붙는다.

```abap
AND zcrm_cicsvc~subs_type = gc_subs_type_s    " SUBS_TYPE = 'S'
```

> **[실측] 2026-09-10 현재 이 조건은 비교 테스트를 위해 주석 처리되어 있다.**
> 그래서 지금은 일반 데이터도 조회된다. 테스트 종료 후 반드시 원복해야 한다.

### 3.4 화면 표시용으로 함께 읽는 데이터 **[개발가이드]**

| 화면 항목 | 원천 |
|---|---|
| 대체자재번호·대체사유 | `KOTD002` (`KSCHL='Z001'`, `VKORG='ASKR'`, 유효기간) → `KONDD` |
| 대체품 자재명·구품번 | `MAKT`, `MARA-BISMT`, 대체사유명 `TVSUT` |
| 회수가능 제조일·보증기간 | `MVKE-PRODH` → `ZCRM_WRTGROUP` (`WRT_TYPE='A'`) |
| 단납 보증기간 | `ZCRM_CICSVC-SERNR` → `ZCRM_WRTDG` (`WRTPER<>0`, `LOEVM<>'X'`)<br>`CIC_YN='C'` 이면 보증기간에 **9개월 가산** |
| 해지 서비스점 자동 부적합 | `KNVV-AUFSD` (`ASKR`/`10`/`10`) = `Z8`, 공백이면 `KNA1-AUFSD` = `Z8`<br>해당 시 `NCF='N'`, `NCF_RSN_V='Z10'` 자동 설정 |
| 해피콜 부적합 | `HNCFRCD` 가 지정 6개 코드이고 `RSLTDATE >= 20140701` 일 때만 표시 |

## 5. 입력과 저장

### 5.1 입력 순서

1. ALV 에서 대상 행을 찾는다.
2. **적합수량** 또는 **부적합수량** 을 입력한다.
3. 부적합수량을 입력했다면 **부적합사유** 를 선택한다.
4. 적합수량을 입력했다면 **책임사업장** 을 입력한다.
5. **회수품 입고일자** 를 입력한다.
6. 화면 상단의 **접수부서명** 과 **접수자** 를 입력한다.
7. **저장(Ctrl+S)** 을 누른다.
8. `저장 하시겠습니까?` 팝업에서 **예** 를 누른다.

![](shots/S10_TC09-01_OLD_4_popup.png)

> **[실측] 주의** ALV 셀에 값을 넣은 뒤 Enter 를 누르면 화면이 서버 값으로 다시 그려지면서
> **입력한 값이 사라진다.** 값을 넣었으면 Enter 없이 바로 저장을 누른다.

### 5.3 저장 전 업무 검증 6종 **[실측]**

하나라도 걸리면 저장되지 않고 상태바에 오류(E)가 표시된다.

| # | 조건 | 메시지 |
|---|---|---|
| 1 | 적합수량 + 부적합수량 > 요청수량 | 적합/부적합 수량의 합은 요청수량을 초과 할 수 없습니다. |
| 2 | 부적합수량 > 0 인데 사유가 없음 | 부적합 사유가 누락 되었습니다. |
| 3 | 부적합수량 = 0 인데 사유가 입력됨 | 부적합 수량이 없는데, 부접합 사유가 있습니다. |
| 4 | 적합수량 > 0 인데 책임사업장이 없음 | 적합 수량이 존재 하면, 책임사업장은 필 수 입니다. |
| 5 | 접수부서명 또는 접수자가 없음 | 접수부서명 또는 접수자가 누락 되었습니다. |
| 6 | 수량을 입력했는데 회수품 입고일자가 없음 | 회수품 입고일자를 입력해주세요 |

![](shots/S10_TC09-01_OLD_4b_after_confirm.png)

> **[실측] 6번만 두 프로그램의 동작이 다르다.**
> 기존은 저장 버튼을 누르는 즉시 차단하고 확인 팝업이 뜨지 않는다.
> 신규는 확인 팝업을 먼저 띄우고 예를 누른 뒤 차단하며, 메시지 끝에 마침표가 있다.

> **[개발가이드]** 해피콜 부적합(`HNCFRCD` 존재)인 경우 `CF_QTY = 0`,
> `NCF_RSN_V = 'Z08'` 조건을 만족해야 한다.

### 5.4 저장되는 테이블 **[실측]**

검증을 통과하면 상태바에 `정상적으로 저장되었습니다.` 가 표시되고 아래 세 테이블이 기록된다.

#### ① ZCRM_RECPTNO — 접수번호 채번

| 필드 | 값 |
|---|---|
| DATUM | 저장일 (예 2026.09.10) |
| SEQNO | 그날의 순번 (1, 2, 3 …) |

접수번호는 **일자 8자리 + 순번 5자리** 로 만들어진다.
예: 2026.09.10 의 1번 → `2026091000001`

#### ② ZCRM_RECPT — 접수·적합성 판정 결과

| 필드 | 저장되는 값 |
|---|---|
| RECPTNO / RECPTNO_ITEM | 채번된 접수번호 / 품목번호 (10) |
| REQNO / REQNO_ITEM | 회수품 요청번호 |
| CSLTNO / CSLTNO_ITEM | 상담번호 |
| RECPTDATE | 저장일 |
| CF_QTY / NCF_QTY | 입력한 적합수량 / 부적합수량 |
| NCF | 적합이면 `Y`, 부적합이면 `N` |
| NCF_RSN_V | 선택한 부적합사유 코드 |
| RSPC | 입력한 책임사업장 |
| STATUS | `X` (접수 완료) |
| CONFDAT | 적합 판정일. **적합 저장일 때만 채워진다** |
| NETWR / WAERS | 금액 / 통화. **적합 저장일 때만 채워진다** |
| REMARK | 입력한 비고 |
| REMARK1 / REMARK2 | 접수부서명 / 접수자 |

#### ③ ZCRM_RECPT_WEAR — 회수품 실제 입고일자

| 필드 | 값 |
|---|---|
| RECPTNO / RECPTNO_ITEM | 접수번호 / 품목번호 |
| WEARDATS | 입력한 회수품 입고일자 |

### 5.5 적합 저장과 부적합 저장의 차이 **[실측]**

| 필드 | 적합수량 저장 | 부적합수량 저장 |
|---|---|---|
| CF_QTY / NCF_QTY | 1 / 0 | 0 / 1 |
| NCF | `Y` | `N` |
| NCF_RSN_V | 공백 | 선택한 코드 (예 `Z02`) |
| RSPC | 필수 입력 | 공백 가능 |
| CONFDAT | 저장일 | 공백 |
| NETWR / WAERS | 금액 · KRW | 공백 |

### 5.6 금액 계산 **[개발가이드]**

가격 기준 자재는 대체자재(`SMATN`)가 있으면 그것을, 없으면 `MATNR_PRT` 를 쓴다.
`A911` (`VKORG='ASKR'`, `VTWEG='10'`, `KSCHL='PR00'`, 유효기간) → `KONP` 에서 단가를 읽어
`NETWR = CF_QTY × KBETR`, `WAERS = KONWA` 로 저장한다.
