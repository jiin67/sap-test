## 5. ALV 컬럼 구성 (TC-06) — 조건부 PASS

### 관측된 차이

| 항목 | 기존 `ZCRMR052` | 신규 `ZCRMR052_S` |
|---|---|---|
| 표시 컬럼 수 | 42 | 44 |

| 구분 | 컬럼 |
|---|---|
| 기존에만 표시 | `NCF_RSN_V` (부적합사유 코드) |
| 신규에만 표시 | `SUBS_TYPE` (비교 제외), `STATUST` (상태), `MULTIKITYN` (멀티킷 사용여부) |
| 컬럼 순서 | 전면 상이 |

공통 41개 컬럼의 **컬럼명(헤더 텍스트)은 모두 동일**하다.

### 원인: 레이아웃(변형) 유무 차이

레이아웃 선택 대화상자를 양쪽에서 열어 확인했다.

| 프로그램 | 저장된 레이아웃 |
|---|---|
| 기존 `ZCRMR052` | **6개**. `/온수매트`, `/적합01`, `/적합02`, **`/CRM01` = 기본 설정**, `/CRM02`, `/NE-3(정지호)` |
| 신규 `ZCRMR052_S` | **0개** |

기존 화면은 기본 레이아웃 `/CRM01` 이 걸러낸 42개 컬럼을 그 레이아웃 순서로 보여주고,
신규 화면은 레이아웃이 없어 프로그램이 정의한 원본 필드카탈로그를 그대로 보여준다.

이것으로 컬럼 순서 차이와, 신규에만 `STATUST`·`MULTIKITYN` 이 보이는 이유가 설명된다.
시나리오상 **ALV Layout Variant 는 비교 제외 항목**이므로 결함으로 보지 않는다.

### 개발자 확인 필요: `NCF_RSN_V`

`NCF_RSN_V` (부적합사유 **코드**)는 기존 화면에 표시되나 신규 화면에는 없다.
신규가 원본 카탈로그를 그대로 보여주는 상태이므로, 이 컬럼이
**신규 프로그램의 필드카탈로그에 없거나 `no_out` 으로 막혀 있을 가능성**이 있다.

ALV 레이아웃 **변경** 대화상자는 스크립팅으로 열지 못했다
(`&OL0`, `&OAD`, `&LAYOUT` 모두 실패). 숨김 컬럼 목록은 확인하지 못했다.

→ **두 프로그램의 필드카탈로그 생성 코드를 직접 비교해 확인할 것.**

`NCF_RSN_VT` (부적합사유 **텍스트**, 편집용 Dropdown)는 양쪽 모두 존재하고
셀 타입도 `ValueList` 로 동일하다. 입력 기능 자체에는 영향이 없어 보인다.

### 셀 속성 비교

같은 레코드(접수번호 `2026070100070`)를 양쪽에서 비교한 결과 편집 가능 필드가 일치했다.

| 프로그램 | 편집 가능 컬럼 |
|---|---|
| 기존 | `WEARDATS` |
| 신규 | `WEARDATS` |

접수 완료 건이라 수량·사유·책임사업장이 모두 잠긴 상태이며 두 프로그램이 같다.
다른 행은 정렬 순서가 달라 같은 레코드가 아니므로 비교에서 제외했다.
편집 제한(TC-12) 전면 검증은 **같은 레코드를 양쪽에서 지정해** 다시 해야 한다.

### 원인과 영향 — 중요

개발자가 **조회 SELECT 두 곳**의 구독조건은 주석 처리했으나,
**저장 경로에는 별도의 구독 검증이 그대로 살아 있다.**
그래서 신규 프로그램은 일반 데이터를 조회는 하지만 저장은 거부한다.

이 때문에 다음 케이스는 현재 상태로 비교가 불가능하다.

| 케이스 | 상태 |
|---|---|
| TC-07 적합수량 저장 | 실행 불가 |
| TC-08 부적합수량 저장 | 실행 불가 |
| TC-09 검증 메시지 (신규 측) | 실행 불가 |
| TC-13 해지 서비스점 자동 부적합 | 실행 불가 |
| TC-16 Header 변경 감지 | 실행 불가 |

> 이 동작 자체는 결함이 아닐 수 있다. 신규 프로그램이 구독 데이터만 처리해야 한다면
> 일반 데이터의 저장 거부는 오히려 정상이다. 다만 회귀 비교 테스트를 막는다.

**진행 방법 두 가지**

1. 저장 검증의 구독 조건도 임시로 주석 처리한다.
   조회 조건과 함께 테스트 종료 후 **양쪽 모두 반드시 원복**한다.
2. `ZCRM_CICSVC-SUBS_TYPE = 'S'` 인 테스트 데이터를 만든다.
   실제 운영 경로를 그대로 검증하므로 이쪽이 낫다.

### DB 안전 확인

12회 실행 모두 저장이 차단되어 DB 는 변경되지 않았다. SE16N 으로 확인했다.

## 7. 결론과 다음 단계

### 결론

구독 구분 필드와 프로그램별 고유 표시 항목을 제외하면, **조회 계열 기능은 기존
`ZCRM052` 와 신규 `ZCRM052_S` 가 동일하게 동작한다.** 조회 건수, 조회 데이터 값,
선택화면 제어, ALV 편집 제한, 상세조회 결과, 종료 동작이 모두 일치했다.

관측된 화면 차이는 ALV 레이아웃(변형) 유무에서 비롯된 것으로 원인이 규명됐으며,
시나리오상 비교 제외 항목이다.

**저장 계열은 아직 판정할 수 없다.** 신규 프로그램의 저장 경로에 구독 검증이
그대로 남아 있어 일반 데이터로는 저장이 거부된다.

### 개발자 확인 요청 2건

| # | 내용 |
|---|---|
| 1 | `NCF_RSN_V` (부적합사유 코드) 가 신규 프로그램 필드카탈로그에 있는지, `no_out` 인지 |
| 2 | 저장 경로 구독 검증의 처리 방침 — 임시 해제할지, 구독 테스트 데이터를 만들지 |

### 저장 계열 재개 조건

아래 둘 중 하나가 충족되면 `scripts/S10_save_test.vbs` 로 즉시 이어서 진행할 수 있다.

1. 저장 검증의 구독 조건을 임시 주석 처리. **조회 조건과 함께 반드시 원복**한다.
2. `ZCRM_CICSVC-SUBS_TYPE = 'S'` 인 테스트 데이터 생성. 실제 운영 경로를 검증하므로 권장.

### 테스트 종료 후 필수 조치

```
AND ZCRM_CICSVC~SUBS_TYPE = GC_SUBS_TYPE_S
```

위 조건을 **회수품 접수 SELECT 와 회수품 미접수 SELECT 양쪽 모두** 원복한다.
저장 검증도 임시 해제했다면 그것도 함께 원복한다.
운영 이관 전 활성화 여부를 별도로 점검한다.
