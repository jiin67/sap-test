B. [필수] ZCRMR058_1F01 - FORM set_mcomp 의 EXIT→CONTINUE 가 엉뚱한 곳에 들어감
-------------------------------------------------------------------------------------
찾는 문자열 :  MESSAGE e050.
위치         :  FORM set_mcomp 안, 348~355행
왜           :  이 IF 는 '이미 확정된(노랑·초록) 줄을 또 선택했을 때' 막는 검사입니다. 0원 대리점과 관계없습니다.
                게다가 MESSAGE e050 은 E 타입이라 그 줄에서 처리가 끝나므로 뒤의 EXIT/CONTINUE 는 실행되지 않습니다.
                → 원래대로 되돌립니다.

현재 (KDD 348~355행)
    IF gt_data_total-zicon <> icon_led_red.
      MESSAGE e050.   "이미 확정된 데이터가 포함 되어 있습니다.
**<<SR03000035400 D-10 (B안)
*0 원 대리점을 그냥 건너뛰고 나머지만 확정위해 EXIT 대신
*      EXIT.
      CONTINUE.
**>>SR03000035400 D-10
    ENDIF.

수정 후 (원복)
    IF gt_data_total-zicon <> icon_led_red.
      MESSAGE e050.   "이미 확정된 데이터가 포함 되어 있습니다.
      EXIT.
    ENDIF.

그리고 '0원 대리점 처리' 는 아래 B-2 로 합니다.

B-2. [필수] ZCRMR058_1F01 - 0원 대리점 검사 블록의 위치와 메시지 타입
-------------------------------------------------------------------------------------
찾는 문자열 :  lv_count = lv_count + 1.      (set_mcomp 안, e050 IF 바로 아래)
현재 상태   :  0원 검사가 385~395행(lt_assptfeeh1 채우는 중간)에 'MESSAGE e001 … EXIT.' 로 있음.
                E 타입이라 선택한 대리점 중 하나만 0원이어도 전체 확정이 멈춥니다.

[방법 1] 0원 대리점만 건너뛰고 나머지는 확정  ← "건너뛰고 나머지만 확정" 이 의도라면 이것
  ① 385~395행의 0원 검사(IF … = 0. MESSAGE … EXIT. ENDIF.) 는 지우고, 헤더 저장 두 줄만 남긴다:
**<<SR03000035400 D-10 (B안) 구독 : 기술료·출장비를 확정 헤더에 저장
    IF gv_subs_mode = 'X'.
      lt_assptfeeh1-maxtechprice = gt_data_total-maxtechprice.
      lt_assptfeeh1-tripprice    = gt_data_total-tripprice.
    ENDIF.
**>>SR03000035400 D-10
  ② 'lv_count = lv_count + 1.' 바로 위에 아래 블록을 넣는다 (건수·노랑 처리 전에 건너뛰어야 하므로 이 위치):
**<<SR03000035400 D-10 (B안) 구독 : 기술료+출장비 = 0 인 대리점은 확정 대상에서 제외
    IF gv_subs_mode = 'X'
   AND gt_data_total-maxtechprice + gt_data_total-tripprice = 0.
      MESSAGE s001 WITH '지급액(기술료+출장비) 0 원 대리점 제외:' gt_data_total-kunnr
              DISPLAY LIKE 'E'.
      CONTINUE.
    ENDIF.
**>>SR03000035400 D-10
    lv_count = lv_count + 1.
  - S 타입 + DISPLAY LIKE 'E' 라야 빨간 메시지를 보여 주면서도 LOOP 가 다음 대리점으로 넘어갑니다.
  - 여러 대리점이 0원이면 마지막 메시지만 보입니다. 모두 보여 주고 싶으면 BAL 로그/팝업이 필요하니 우선은 이대로.

[방법 2] 0원이 하나라도 있으면 전체 확정 중단
  - 지금 385~395행 그대로 두면 됩니다(MESSAGE e001 … EXIT). B 의 원복만 하면 끝.

어느 쪽이든 결과서에는 '기존: 0원 검사 없음 / 변경: 0원 대리점 확정 제외(또는 중단)' 로 적습니다.

C. [권장] ZCRMR060_1F01 - 기사별 금액 행(line_idx = 2) 계산을 IF 밖으로
-------------------------------------------------------------------------------------
찾는 문자열 :  ELSEIF gt_data1-line_idx = 2.        (1546행 부근)
왜           :  CLEAR·assptfee 계산·MODIFY 가 'IF sy-subrc = 0' 안에 있어, 기술료·출장비 행이 없는 기사는
                READ 가 실패해 금액 행이 건수 단가(5,000 …)로 남습니다. 구독은 단가를 안 주기로 했으니 0 이어야 합니다.

      ELSEIF gt_data1-line_idx = 2.
        READ TABLE gt_cost_sum2 WITH KEY kunnr    = gt_data1-kunnr
                                         techname = gt_data1-techname.
        IF sy-subrc = 0.
          gt_data1-maxtechprice = gt_cost_sum2-maxtechprice.
          gt_data1-tripprice    = gt_cost_sum2-tripprice.
**<<SR03000035400 D-10 (B안) 구독 지원금 = 기술료 + 출장비, 건수 단가 제외
        CLEAR: gt_data1-night, gt_data1-deepnight, gt_data1-weekday, gt_data1-holiday.
        gt_data1-assptfee = gt_data1-maxtechprice + gt_data1-tripprice.
**>>SR03000035400 D-10
          MODIFY gt_data1.
        ENDIF.

수정 후
      ELSEIF gt_data1-line_idx = 2.
        CLEAR: gt_data1-maxtechprice, gt_data1-tripprice.
        READ TABLE gt_cost_sum2 WITH KEY kunnr    = gt_data1-kunnr
                                         techname = gt_data1-techname.
        IF sy-subrc = 0.
          gt_data1-maxtechprice = gt_cost_sum2-maxtechprice.
          gt_data1-tripprice    = gt_cost_sum2-tripprice.
        ENDIF.
**<<SR03000035400 D-10 (B안) 구독 지원금 = 기술료 + 출장비, 건수 단가 제외 (비용 행이 없는 기사는 0)
        CLEAR: gt_data1-night, gt_data1-deepnight, gt_data1-weekday, gt_data1-holiday.
        gt_data1-assptfee = gt_data1-maxtechprice + gt_data1-tripprice.
        MODIFY gt_data1.
**>>SR03000035400 D-10
      ENDIF.

합계 행(999, 1535~1545행)은 LOOP 로 누적하고 MODIFY 가 밖에 있어 그대로 두면 됩니다.
