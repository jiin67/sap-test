D-09 수정 확인 수동 절차 (SR03000035400, KDQ 210)                      2026-10-02
=====================================================================================

목적
  ZCRM177AS 에서 구독 상담건을 문서처리했을 때 ZCRM_ORDER_AUTO 의 PROGRAM_NM 이
  'ZCRM177AS' 로 기록되는지 확인한다. (수정 전에는 구독 건도 'ZCRM177A' 였음)

소요 시간  약 30분.   필요한 것  KDQ 210 로그온, SE38 조회 권한, SE16N 편집 권한.

-------------------------------------------------------------------------------------
0. 먼저 할 것 (스크립트가 멈춰 있는 상태 해소)
-------------------------------------------------------------------------------------
  0-1. KDQ 세션이 'Import 큐: 시스템 KDQ' 화면에 있으면 명령창에 /n 을 치고 Enter 로
       초기화면(SAP Easy Access)으로 나온다.
  0-2. KDD 세션의 '전체전송로그 개요' 화면도 /n 으로 나온다.
  0-3. 두 세션을 나오면 멈춰 있던 제 스크립트가 자동으로 이어진다. 끝나지 않더라도
       아래 작업에는 지장이 없다. (스크립트를 강제로 끊지 않아도 된다)

-------------------------------------------------------------------------------------
1. D-09 소스 수정이 KDQ 에 들어왔는지 확인 (SE38, 조회만)
-------------------------------------------------------------------------------------
  1-1. T-code SE38 → 프로그램 ZCRMR177_1F01 → '소스코드' 라디오 → 조회(안경 아이콘)
  1-2. 찾기(Ctrl+F) → 검색어  gt_auto-program_nm   → '소스코드 전체' 로 찾기
  1-3. 세 군데가 나온다. 각각 바로 위의 IF 문을 본다.
         약 960행   주문 생성 뒤
         약 1205행  납품 생성 뒤
         약 1339행  출고 전기 뒤
       기대:   IF gv_subs_mode = 'X'.
                 gt_auto-program_nm = gc_tcode_subs.
               ELSE.
                 gt_auto-program_nm = 'ZCRM177A'.
               ENDIF.
       세 곳 모두 gv_subs_mode 면 반영된 것.  아직 sy-tcode = gc_tcode_subs 이면
       KDQ 이관이 안 된 것이니 이관 상태(STMS)를 먼저 확인한다.
  1-4. (선택) 메인 프로그램 ZCRMR177_1 70행에
         gv_subs_mode = COND #( WHEN sy-tcode = gc_tcode_subs THEN 'X' ).
       가 있는지도 본다. 10-02 오전에 확인했을 때는 있었다.

-------------------------------------------------------------------------------------
2. 재고가 있는 센터 고르기
-------------------------------------------------------------------------------------
  177 은 상담건의 센터(CENTER_CD) = 저장위치 로 출고하므로, 그 센터 창고에 부품 재고가
  있어야 납품·출고까지 된다.
  2-1. SE16N → 테이블 MARD → 조건
         자재번호 = 30031356A
         플랜트   = 1120
       → 실행 → LABST(가용재고) 가 1 이상인 저장위치(LGORT) 를 본다.
  2-2. 10-02 오전 기준 재고가 남아 있던 센터 (오늘 테스트에서 CT18·CT08·CT14·CT23 은 소진)
         CT11 3 / CT19 2 / CT02·CT05·CT06·CT07·CT09·CT10·CT13·CT15·CT20·CT21 각 1
       → 권장: CT11 (재고 3). 이 절차는 CT11 기준으로 쓴다.
  2-3. 센터 CT11 소속 대리점 하나를 쓴다. 예: 100250 (서귀포대리점, 이전 테스트 사용)
       (177 에는 대리점이 중요하지 않다. KNVV 영업소가 CT11 인 대리점이면 된다)

-------------------------------------------------------------------------------------
3. 상담건 만들기 (SE16N 편집 - 기존 테스트 행을 복사해서 번호만 바꾼다)
-------------------------------------------------------------------------------------
  새 상담번호
     2026100290011  구독 (D-09 확인용, 필수)
     2026100290012  일반 (ZCRM177A 쪽이 그대로 'ZCRM177A' 인지 보는 용도, 선택)
  복사 원본 (오늘 만든 완전한 행)
     구독 원본  2026100290001      일반 원본  2026100290004

  177 에 필요한 테이블은 4개다. (ZCRM_CICSVC_NEW·ZCRM_REQ·ZCRM_CHRG_CNFRM 은 052/171/058 용이라 이번엔 불필요)

  공통 조작 방법 (테이블마다 반복)
    a. SE16N → 테이블명 입력 → Enter
    b. '엔트리 유지보수' 체크박스 ON   (명령창에 &SAP_EDIT 를 쳐도 된다)
    c. 조건  상담번호 = 2026100290001  (원본) → 실행
    d. 결과 행을 선택(행 머리 클릭) → 툴바의 '행 복사' 버튼 (복사 아이콘, 툴팁 "행 복사")
       → 아래에 같은 내용의 새 행이 생긴다
    e. 새 행에서 아래 표의 필드를 바꾼다 (더블클릭해서 수정)
    f. 저장(Ctrl+S) → '변경 완료' 팝업에 삽입 1 / 변경 0 / 삭제 0 인지 확인
    g. 끝나면 반드시 '엔트리 유지보수' 체크박스를 다시 OFF 한다

  3-1. ZCRM_CICSVC  (원본 2026100290001 → 새 행)
         CSLTNO        2026100290011
         TAGNO         9911
         KUNNR_SVC     100250
         SVCNAME       ZTEST_서귀포대리점
         VKBUR         CT11
         RSLTDATE      오늘 날짜 (예 2026.10.02)   ← 177 조치일자와 맞출 필요는 없음
         REGDATE       오늘 날짜
         ERNAM / AENAM ZTEST1002F            ← 나중에 찾기 쉽게
         (SUBS_TYPE=S, SUBSWRTMONTH=12, ISTDATE 2023.10.01, WRTDATE 2026.10.01,
          PRDDATE_PRT 2025.12.13, MATNR_PRT 30031356A, CLMART=A 는 원본 그대로 둔다)
       일반 건(선택): 원본 2026100290004 → CSLTNO 2026100290012, TAGNO 9912,
         KUNNR_SVC 100250, SVCNAME ZTEST_서귀포대리점, VKBUR CT11, ERNAM ZTEST1002F
         (SUBS_TYPE 공백, SUBSWRTMONTH 0 그대로)

  3-2. ZCRM_CICCOST_M  (원본 2026100290001)
         CSLTNO        2026100290011
         CENTER_CD     CT11                   ← 출고 저장위치. 재고 있는 센터여야 함
         INDATE        오늘 날짜              ← 177 선택화면 '조치일자' 로 조회하는 값
         TEXTINFO      ZTEST_20261002F D09
         ERNAM         ZTEST1002F
         VBELN_VA_FD / VBELN_VL_FD / STATUS1_FD~3_FD 가 비어 있는지 확인
           (원본에는 오늘 처리한 오더·납품번호와 @08@ 아이콘이 들어 있다 → 반드시 지운다)
       일반 건(선택): 원본 2026100290004 → CSLTNO 2026100290012, 나머지 동일

  3-3. ZCRM_CICCOST_SUB  (원본 2026100290001)

       일반 건(선택): CSLTNO 2026100290012

  3-4. ZCRM_CICCOST_ADD  (원본 2026100290001)
         CSLTNO        2026100290011

       일반 건(선택): CSLTNO 2026100290012

  3-5. 확인: SE16N (편집 OFF) → ZCRM_CICCOST_M, 상담번호 = 2026100290011 →
       VKORG = ASKR, CENTER_CD = CT11, INDATE = 오늘, VBELN_* 비어 있음.
       → VKORG 가 비어 있으면 복사가 아니라 빈 행 추가로 들어간 것이니 3-2 를 다시 한다.

-------------------------------------------------------------------------------------
4. ZCRM177AS 로 문서처리
-------------------------------------------------------------------------------------
  4-1. T-code ZCRM177AS → 조치일자 = 오늘 ~ 오늘 (3-2 의 INDATE), 상담번호 2026100290011
       → 실행
  4-2. 제목이 '[구독] AS 비용처리' 이고, 2026100290011 이 '구독무상(3년이후)' 로 1건 보이는지 확인
  4-3. 행 체크 → 주문 → (완료 후) 체크 → 납품 → 체크 → 출고
       (주문만 해도 D-09 확인은 되지만, 세 곳이 모두 고쳐졌는지 보려면 출고까지 한다)
  4-4. 일반 건(선택): ZCRM177A → 같은 조치일자, 상담번호 2026100290012 → 주문 → 납품 → 출고

-------------------------------------------------------------------------------------
5. 결과 확인 (SE16N, 편집 OFF)
-------------------------------------------------------------------------------------
  5-1. SE16N → ZCRM_ORDER_AUTO → 조건  상담번호 = 2026100290011 → 실행
         기대: 3행 (오더 429xxxx / 납품 8585xxxx / 자재문서 49219xxxx)
               PROGRAM_NM 세 행 모두 ZCRM177AS      ← 이것이 D-09 해결 판정
  5-2. 일반 건을 했다면  상담번호 = 2026100290012 → PROGRAM_NM 세 행 모두 ZCRM177A
  5-3. (참고) ZCRM_CICCOST_M 2026100290011 의 VBELN_VA_FD / VBELN_VL_FD 에 번호가 들어가고
       STATUS1_FD~3_FD 가 @08@(초록) 이면 문서처리 정상

-------------------------------------------------------------------------------------
6. 저에게 알려 주실 것
-------------------------------------------------------------------------------------
  - 5-1 의 PROGRAM_NM 값 (화면 캡처가 있으면 더 좋음)
  - 만든 상담번호와 오더·납품·자재문서 번호
  - 1-3 에서 본 소스 상태 (gv_subs_mode 로 바뀌어 있었는지)
  → 받으면 결과서 v1.01 (E-05 PASS, D-09 해결) 로 갱신해 드린다.

-------------------------------------------------------------------------------------
주의
-------------------------------------------------------------------------------------
  - SE16N 편집은 QA(KDQ) 에서만. 작업 후 '엔트리 유지보수' 체크박스 OFF.
  - 복사한 행의 CSLTNO 를 바꾸지 않고 저장하면 키 중복으로 저장이 안 되거나 원본이 바뀔 수 있다.
    저장 팝업의 '삽입 1 / 변경 0' 을 꼭 확인한다.
  - ZCRM_CICCOST_M 원본에 든 오더·납품번호(VBELN_*_FD)와 상태 아이콘을 지우지 않으면
    177 에서 '이미 처리된 건' 으로 보여 체크가 안 된다.
  - 재고가 없는 센터를 쓰면 주문은 되고 납품에서 막힌다 (오더만 남음).
