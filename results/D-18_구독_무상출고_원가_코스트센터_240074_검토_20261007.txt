2. 240074 로 보내는 방법 (3가지)
------------------------------------------------------------------------------------
[A] 표준 SD 코스트센터 결정 사용 - 권장 후보 (설정 + ZCRMR177_1 한 줄)
   1) 주문사유 신설: 예) Z0S '구독 무상 AS' (SD 주문사유 정의)
   2) OVF3(TVAUK): 영업영역 ASKR / 10 / 10 + 주문사유 Z0S → 코스트센터 240074
   3) ZCRMR177_1 F01 ~590행 오더 헤더 세팅에서 구독 모드이면 주문사유를 Z0S 로:
        ls_order_header_in-ord_reason = COND #( WHEN gv_subs_mode = 'X' THEN 'Z0S' ELSE '현재값(Z04)' ).
        ls_order_header_inx-ord_reason = 'X'.
      → 오더 생성 시 VBAK-KOSTL = 240074 가 채워지고, 표준 출고는 오더 헤더 코스트센터를 자재문서(MSEG-KOSTL)에 넘긴다.
   확인할 것: ZFD1/품목범주의 계정지정이 헤더 코스트센터를 허용하는지, 그리고 1절의 '저장위치→센터' 로직이 이 값을 덮어쓰지 않는지(테스트로 확인).
   장점: 코드 변경이 한 줄, 구독/일반 구분이 주문사유에 남아 추적 쉬움. 단점: 기존 파생 로직과 충돌 가능.

[B] 기존 파생 로직(1절에서 찾은 BAdI/확장)에 구독 분기 추가
   출고 시 저장위치로 코스트센터를 정하는 곳에서, 납품 → 오더(LIPS-VGBEL) → ZCRM_ORDER_AUTO(PROGRAM_NM = 'ZCRM177AS') 또는 VBAK-AUGRU(= Z0S) 를 보고
   구독이면 240074, 아니면 기존대로. 장점: 한 곳에서 일관 처리. 단점: 구현체를 먼저 찾아야 하고 표준 MM 처리 안이라 영향 범위 검토 필요.

[C] 오더 생성 뒤 VBAK-KOSTL 을 직접 세팅
   BAPI_SALESORDER_CREATEFROMDAT2 헤더 구조에는 코스트센터 필드가 없으므로 생성 후 VA02 BDC(헤더 계정지정 탭 VBAK-KOSTL) 또는 BAPI_SALESORDER_CHANGE + 확장으로 240074 입력.
   [A] 와 결과는 같지만 BDC 가 하나 더 늘어 권장하지 않음.
